## How `node_modules/` and `dist/` come to exist

Neither is checked into git (see `.gitignore`), both are fully
regenerated by machine:

- **`node_modules/`** comes from `npm install`, driven by `package.json`
  and pinned by `package-lock.json`. Two dev dependencies only:
  `typescript` and `@types/node`. There are no runtime dependencies,
  the published package has zero deps.
- **`dist/`** comes from `npm run build` (which is just `tsc`).
  `tsconfig.json` points `rootDir` at `src/`, `outDir` at `dist/`, and
  turns on `declaration`/`declarationMap`/`sourceMap`, so compiling
  produces `.js`, `.d.ts`, and `.map` files for every source file. This
  is what `npm test` actually runs (`node dist/test.js`), and it's what
  gets published to npm (see `RELEASING.md`).

## Rebuilding from zero, no human required

Every step below is a shell command or a file write. An automated agent
can run this sequence top to bottom against an empty directory and end
up with a repo equivalent to this one.

**1. Scaffold the project.**

```bash
mkdir landonkea-type-utils && cd landonkea-type-utils
git init
npm init -y
npm install -D typescript @types/node
```

**2. Write `tsconfig.json`:**

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "lib": ["ES2020"],
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

**3. Write `package.json`** (merge into the one `npm init -y` produced):
name `landonkea-type-utils`, `main: dist/index.js`, `types: dist/index.d.ts`,
scripts `build: tsc`, `test: node dist/test.js`, `dev: tsc && node dist/test.js`,
license `MIT`, zero runtime dependencies.

**4. Write the source files under `src/`.** This is the one step that
genuinely requires generating logic, not just copying config. The
functions to implement, with their exact signatures and behavior, are
listed in `README.md`'s API tables (`string-utils.ts`: `capitalize`,
`camelCase`, `snakeCase`, `truncate`, `isPalindrome`,
`countOccurrences`, `extractEmails`; `array-utils.ts`: `unique`, `chunk`,
`flatten`, `groupBy`, `sortByFields`, `difference`, `intersection`).
`index.ts` re-exports all of them. If this repo is available as a
reference, the simplest correct path is to copy `src/*.ts` verbatim,
they're the source of truth for exact behavior (see the WHAT/HOW/WHY
comment above each function for the reasoning, not just the result).

**5. Write `src/test.ts`** with the two hand-rolled assertion helpers
(`assertEqual` for primitives, `assertArrayEqual` for arrays compared via
`JSON.stringify`) and one test per documented behavior and edge case
(empty string, no truncation needed, case sensitivity, overlapping
substring matches, and so on, see the existing `test.ts` for the full
list of 32).

**6. Write `.gitignore`:**

```
node_modules/
dist/
.vscode/
.idea/
*.swp
*.swo
.DS_Store
Thumbs.db
*.log
npm-debug.log*
coverage/
.nyc_output/
```

**7. Build and verify.**

```bash
npm run build
npm test
```

All 32 tests should pass, exit code 0.

**8. Add the CI workflows** (copy `.github/workflows/ci.yml` and
`.github/workflows/ai-attribution-check.yml` verbatim, both are checked
into this repo and neither depends on anything outside itself).

**9. Add the release workflows** (`.github/workflows/prerelease.yml` and
`.github/workflows/release.yml`), described in full in `RELEASING.md`.
This is also when `package.json` picks up the fields `npm publish` cares
about: `files: ["dist"]` (so the tarball ships compiled output only, not
`src/`), `repository`, and `publishConfig.access: "public"`. These
require one manual, human step that cannot be automated: adding an
`NPM_TOKEN` secret to the GitHub repo settings. No token is generated or
guessed here, that has to come from a real npm account.

**10. Write `README.md`, `docs/DESIGN.md`, `LICENSE`, and this file.**

**11. Commit and push.**

```bash
git add -A
git commit -m "feat: initial commit"
git remote add origin git@github.com:landonkea/landonkea-type-utils.git
git push -u origin main
```

The only step in this whole sequence that a script can't do unattended
is adding the npm publish token in step 9. Everything else, including
writing the source code, running the build, and running the tests, is
fully scriptable.
